## 1. 测试环境与方法

- 浏览器：`%LOCALAPPDATA%\ms-playwright\chromium-1228`（MV3 需 headless:false；品牌版 Chrome 137+ 已移除 --load-extension）
- 扩展：`npm run build` 产物 `dist/`（v1.1.0，构建时间 2026-08-06）
- 每站点流程：入口页 →（运行时发现内容页链接）→ 内容页 → 静态等待 → 探针 + 功能检查 → 截图
- 探针说明：
  - `registrationSwallow`：注册源码含 `preventDefault` 的 keydown 监听器后派发事件，带扩展时**不触发**（证明注册吞没生效）
  - `runtimeNeutralize`：object-form(handleEvent) 监听器（绕过源码过滤）调用 `preventDefault()`，带扩展时 `defaultPrevented===false`（证明运行时中和生效）
  - 两个探针在全部 8 站的扩展上下文均为 true、基线均为 false，证明 DEBT-03 两套机制在真实站点全量生效
- 复制端到端：鼠标拖拽产生真实选区 → `Control+C` → `navigator.clipboard.readText()` 比对（已授予剪贴板权限）

## 3. 高交互对照站详表与误伤证据

### 3.1 B站（确认误伤）

基线与扩展上下文均能播放视频，空格暂停/继续、方向键 ±5s seek 均正常，搜索框输入正常。**但**：

| 检查项 | 基线 | 扩展 | 判定 |
| :--- | :--- | :--- | :--- |
| 播放器右键定制菜单（bpx-player-contextmenu） | ✅ 弹出 | ❌ 不出现（0 个节点） | 🔴 误伤 |
| 被吞监听器计数 | 0 | mousedown×11, keydown×2, keyup×1, contextmenu×2, paste×1, dragstart×1 | 🔴 机制证据 |
| 播放/空格/方向键/搜索输入 | ✅ | ✅（二轮修正焦点污染后） | 通过 |

归因：右键菜单失效由两层叠加造成——
1. `content/content.js` 的 `removeGlobalRestrictions()` 在 document **捕获阶段**对 contextmenu 注册 `allowDefaultHandler` 并调用 `stopPropagation()`，事件根本到不了播放器的目标阶段处理器；
2. `content/injector.js` 吞掉 2 个源码含 preventDefault 的 contextmenu 监听器 + 运行时中和 preventDefault，站点无法抑制原生菜单。

被吞的 keydown×2/keyup×1 的原始职能未能定位（可能属弹幕输入/画质切换等未测功能），核心快捷键幸存是因为 B 站绑定了多个 keydown 监听器、快捷键派发器源码不含限制性 token。**"测到的都正常"不等于"无损"——被吞监听器的职能不可枚举，这是注册吞没机制的固有盲区。**

### 3.2 道客巴巴（发现 P0 缺陷：拦截路径抛异常）

**根因（基线上下文同样复现，与扩展无关的页面事实）**：道客巴巴文档页的脚本将全局 `Map` 替换为非原生实现——`Map.prototype.has/set === undefined`、`Map.toString()` 不含 `[native code]`，`new Map().set()` 直接抛 `TypeError`。

**扩展放大了这个页面缺陷**：injector 的 `interceptedListeners = new Map()` 产出的对象没有 `.has/.set`，于是每当页面注册"源码含 preventDefault"的监听器，`overriddenAddEventListener` 就抛出：

```
TypeError: interceptedListeners.has is not a function
    at HTMLDocument.overriddenAddEventListener
```

该异常**穿透进页面自身脚本的调用栈**——页面脚本在 addEventListener 调用处中断执行，后续语句全部丢失。实测扩展上下文注册探针监听器 100% 复现抛错；基线无扩展则正常。道客巴巴文档能渲染不代表无损：依赖"被炸断的脚本块"的功能会静默失效。

> 附带发现：该站对全局对象的篡改同时导致 Playwright `page.evaluate` 返回对象时序列化为 `undefined`（其序列化器依赖 Map），首轮 `unlock:{}` 的异常读数由此而来。这解释了现象，不影响缺陷结论。

### 3.3 YouTube / Google Docs（环境受限）

- YouTube：首页可达但视频页停留在 t=0 且页面脚本对 evaluate 无响应（"确认你不是机器人"风控的典型表现），扩展上下文浏览器进程还发生了一次崩溃。无法验证播放器快捷键。
- Google Docs：重定向 accounts.google.com 登录页。登录页输入打字正常；但注意到 **injector 在 Google 账号登录页全量运行**（`<all_urls>` + 默认启用），高价值账号页面承受原型重写暴露面，建议产品层面评估（见 R5）。

## 4. DEBT-03 拦截策略收敛建议（R1–R5）

### R1（P0，上架前必做）：拦截路径零异常

`content/injector.js` 的注册吞没路径不得向页面抛出异常：

- `interceptedListeners` 的读写包 try/catch——存取失败只丢调试信息，吞没决策本身绝不抛错（该 Map 仅用于调试暴露与 disable 时 clear，被吞监听器本来就不会被恢复，容错成本低）；
- `isRestrictiveListener` 的 catch 分支当前"出错即视为限制性"（fail-closed 吞掉），建议反转为 fail-open（出错不吞）+ 计数日志：运行时中和已对 preventDefault 兜底，误吞的代价（功能丢失）大于漏吞（该监听器内的 preventDefault 仍被中和）。

### R2（P1）：拆分"注册吞没名单"与"运行时中和名单"，收窄前者

当前 10 类事件同时被两套机制覆盖。建议：

```js
// 注册吞没（源码正则，破坏性最强）：只保留纯限制向事件
const swallowEvents = ['selectstart', 'contextmenu', 'dragstart', 'copy', 'cut', 'paste'];

// 运行时中和（preventDefault/stopPropagation 失效化）：吞没名单 + 以下
const neutralizeEvents = [...swallowEvents, 'mousedown', 'keydown', 'keyup'];
// keydown/keyup 加修饰键门控：仅当 ctrlKey||metaKey 时中和，
// 精准击穿"Ctrl+C/V/X 封锁"（文库类），放行播放器空格/方向键的 preventDefault
```

- **keydown/keyup/mousedown 退出注册吞没名单**：B站实证这3类吞了 14 个中的 14 个（除 contextmenu×2/paste×1/dragstart×1 外全部），播放器/编辑器快捷键的主要死因；
- **mouseup 整体移除**：无主流站点用 mouseup 实施复制限制；
- mousedown 保留运行时中和（击穿 mousedown 级选择封锁）；可选精化：事件目标位于 `input/textarea/[contenteditable]` 内时不中和（保护富文本编辑器工具栏的焦点保持模式）；
- contextmenu 维持现状（原生菜单优先于站点定制菜单，这是产品使命决定的默认取舍），但需配合 R5 提供站点级逃生通道。

### R3（P1）：content.js 捕获放行处理器去掉 stopPropagation

`content/content.js:699` 的 `allowDefaultHandler` 在 document 捕获阶段对 selectstart/contextmenu/dragstart/copy 一律 `stopPropagation()`，事件到不了站点目标阶段处理器（B站定制右键菜单的直接死因之一）。该 stopPropagation 的解锁价值与 injector 的运行时中和**冗余**（preventDefault 已被中和，站点处理器执行与否不影响默认行为），建议移除 stopPropagation 调用（保留处理器注册或整体删除这组捕获监听）。

注意：对 contextmenu 而言，移除后若站点菜单处理器幸存，会出现"定制菜单+原生菜单"双弹——因此 R3 建议与 R2 联动评估，contextmenu 也可选择维持全拦截现状。

### R4（P2）：injector 日志静音

每个拦截动作都 console.log（豆丁单页 134 条）。建议默认静音，由 DEBT-05 已持久化的 `debugMode` 设置经 postMessage 开启（顺带为 DEBT-05 提供一个真实消费方）。

### R5（P2）：产品级配套

- **站点排除列表缺失**：当前只有 AUTO_ENABLE_LIST（自动开启白名单），默认全局启用，用户遭遇误伤站点只能整站关闭插件。建议 options 增加"排除列表"（或把 popup 的站点开关持久化为黑名单），这是 R2 contextmenu 取舍的用户逃生通道；
- object-form(handleEvent) 监听器完全绕过源码过滤（探针实证），运行时中和仍兜底，登记为已知限制即可；
- injector 在 accounts.google.com 等账号页全量运行，建议随排除列表内置少量敏感域名默认排除；
- `addEventListenerWrapped` 类 toString 检测在站点叠加自身 hook 时会误报（CSDN 实证：站点在我们的重写之上又包了一层），自检逻辑勿依赖 toString。

## 5. 权限审计结论

`manifest.json` 的 `"management"` 权限：**全仓无任何 `chrome.management` API 调用**（其余 "management" 字样均为数据管理 UI 文案与 i18n 字符串）。建议移除该行（manifest.json 第 12 行），降低商店审核阻力。

## 7. 测量限制

1. 知乎/YouTube/Google Docs 受反爬与登录墙限制未能完成功能验证，建议登录态人工复核；
2. 百度文库未能发现文档直链，文库阅读器内的解锁效果未验证（历史上文库是 Ctrl+C keydown 封锁的典型，R2 的修饰键门控设计已保留该场景的击穿能力，但需实测确认）；
3. 运行时内容页由入口页链接动态发现，样本随时间漂移（道客巴巴三轮采样到 4 个不同文档）；
4. B站被吞监听器的原始职能无法从外部枚举，"核心交互正常"不等于全功能无损。
