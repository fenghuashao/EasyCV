# EasyCV 部署文档

## 📋 部署概述

本文档说明 EasyCV 当前仓库下真实可执行的构建、打包、版本更新与部署准备流程。目标是让维护者能够基于现有脚本完成发布准备，而不是依赖过时模板或占位配置。

## 🛠️ 仓库与环境

### 仓库信息
- **GitHub 仓库**: `https://github.com/fenghuashao/EasyCV`
- **默认分支**: `master`
- **扩展规范**: Chrome Extension Manifest V3

### 系统要求
- **浏览器**: Chrome 88+ 或 Edge 88+
- **Node.js**: 建议使用 Node 20+
- **npm**: 建议使用 npm 10+
- **操作系统**: Windows 10+、macOS 10.14+、Linux

### 获取项目
```bash
git clone https://github.com/fenghuashao/EasyCV.git
cd EasyCV
npm install
```

> 说明：当前项目依赖较少，主要开发脚本使用本地 Node.js 运行；`npm install` 会安装打包所需依赖。

## 🏗️ 当前脚本入口

下表对应的是当前 `package.json` 中真实存在的命令：

| 命令 | 当前行为 | 适用场景 |
| --- | --- | --- |
| `npm run docs:check` | 检查索引链接、占位内容、以及索引纳管文档中的仓库路径引用 | 改文档后先跑 |
| `npm run lint` | 当前为占位入口，输出 `Linting code...` | 保留为后续接入真实 lint 的入口 |
| `npm run test` | 当前为占位入口，输出 `Running tests...` | 保留为后续接入真实测试的入口 |
| `npm run build` | 执行 `scripts/build.js`，先校验 manifest、HTML 脚本与 `importScripts` 引用完整性，再复制扩展文件到 `dist` 并生成构建信息 | 本地构建、发布前验证 |
| `npm run package` | 执行 `build + zip`，生成发布包 | 需要 ZIP 发布包时 |
| `npm run zip` | 执行 `scripts/package.js`，把现有 `dist` 打包到 `releases` | 已构建后单独打包 |
| `npm run clean` | 执行 `scripts/clean.js`，清理构建产物、发布产物与常见临时文件 | 重新构建前清理 |
| `npm run bump:patch` / `minor` / `major` | 执行 `scripts/bump-version.js`，同步更新 `package.json`、`manifest.json` 与 `CHANGELOG.md` | 版本递增 |
| `npm run release` | 执行 `clean + build + package` | 本地完整发布准备 |
| `npm run deploy` | 执行 `scripts/deploy.js` 的完整部署流程 | 需要统一跑验证、构建、打包时 |
| `npm run deploy:patch` / `minor` / `major` | 先更新版本，再执行部署流程 | 发版时顺带递增版本 |
| `npm run deploy:build-only` | 仅执行构建 | 验证构建是否正常 |
| `npm run deploy:dry-run` | 预览部署步骤，不实际修改文件 | 发布前检查流程 |

## 📦 推荐发布准备流程

### 1. 文档与基础校验
```bash
npm run docs:check
npm run lint
npm run test
```

> 注意：当前 `lint` 与 `test` 还是占位入口，真正有价值的硬校验是 `docs:check` 与 `build`。如果要上线发布，仍建议补充人工功能验证。

### 2. 构建与打包
```bash
npm run build
npm run package
```

构建成功后：
- 扩展文件会输出到 `dist`
- ZIP 发布包会输出到 `releases`
- 打包脚本会生成发布说明，并在 Windows/macOS 上尝试自动解压 ZIP 供快速检查

### 3. 带版本更新的发布准备
```bash
npm run deploy:patch
```

该流程会依次执行：
1. 环境验证
2. 内置测试步骤（当前为脚本内模拟流程）
3. 版本更新
4. 清理旧产物
5. 重新构建
6. 打包
7. 生成部署报告

### 4. 仅预览部署流程
```bash
npm run deploy:dry-run
```

适合在真正发版前先确认步骤顺序、版本更新与构建打包策略。

## 🔢 版本管理

当前版本管理由 `scripts/bump-version.js` 负责：

- 同步更新 `package.json`
- 同步更新 `manifest.json`
- 自动写入 `CHANGELOG.md`

版本规则：
- **patch**: 问题修复
- **minor**: 向下兼容的新功能
- **major**: 不兼容变更

常用命令：
```bash
npm run bump:patch
npm run bump:minor
npm run bump:major
```

## 📁 当前产物说明

### 构建产物
- `dist` 目录：可直接用于浏览器“加载已解压的扩展程序”
- `build-info.json`：记录构建时间与构建号

### 发布产物
执行打包后，通常会生成：
- ZIP 发布包，命名模式为 `EasyCV-v<version>-YYYYMMDD.zip`
- 发布说明，命名模式为 `EasyCV-v<version>-README.md`

执行 `npm run deploy` 或 `npm run deploy:<type>` 时，还会额外生成部署报告 `deploy-report.json`。

这些文件由脚本生成，默认输出到 `releases` 目录。

## 🧪 发布前人工检查

在当前仓库状态下，建议至少完成以下人工检查：

- [ ] `npm run docs:check` 通过
- [ ] `npm run build` 通过
- [ ] 能在 Chrome 中成功加载 `dist`
- [ ] Popup、Options、Content Script 基本功能可用
- [ ] 版本号与 `manifest.json` 一致
- [ ] 打包后的 ZIP 可以正常解压并加载

## 🌐 商店发布与手动分发

### Chrome Web Store / Edge Add-ons
当前仓库**没有**内置商店自动发布脚本。商店发布仍需人工完成：

1. 本地执行 `npm run package` 或 `npm run deploy`
2. 取生成的 ZIP 发布包
3. 登录对应的商店后台
4. 上传 ZIP、填写商店描述、截图和隐私说明
5. 提交审核

### 手动分发
如果只是内部试用或手动安装：

1. 运行 `npm run build`
2. 直接加载 `dist` 目录  
   或
3. 运行 `npm run package`，分发 ZIP 后由接收者解压加载

## 🔧 常见问题

### `npm run build` 失败
- 检查 `manifest.json` 是否有效
- 检查 `background`、`content`、`popup`、`options`、`utils`、`icons` 是否存在

### `npm run package` 失败
- 先确认 `dist` 已存在
- 重新执行 `npm run build`
- 再执行 `npm run package`

### `npm run deploy` 失败
- 先执行 `npm run deploy:dry-run` 查看流程
- 检查版本号写入是否正常
- 检查 `releases` 目录是否被其他程序占用
