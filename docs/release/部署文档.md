# EasyCV 部署文档

## 仓库维护入口（2026-11-09）

常规贡献流程见[贡献指南](../../.github/CONTRIBUTING.md)。GitHub 的 CI 运行安装、语法、单元、文档与隔离打包检查，不提交商店。Windows 快速打包入口已迁到 `scripts/package-quick.bat`。后台展示属性与安全开关的建议及边界见[仓库配置说明](./github-repository-settings.md)。以下候选记录保留各自日期的状态。

## 四语言候选注意事项（2026-11-03）

当前源码默认语言改为 `en`，并包含 `zh_CN`、`ja`、`zh_TW`。本轮仅执行本地验证，不提交或发布，版本号保持不变。后续获得发布授权后，需核对开发者后台的默认语言与扩展一致，并维护四种语言的商店详细介绍及截图；本地 `_locales` 修改不会自动更新这些商店材料。新旧源码必须重新构建校验，不能沿用旧 ZIP 的语言验收结论。

## 当前本地候选流程（2026-11-03，优先于下文旧命令示例）

- `node scripts/build.js --out .tmp/一个全新目录/dist`：输出目录必须在项目内，且不能覆盖非空目录或源目录。manifest/package/lock 根版本必须一致。
- `npm run package:quick`：在独立 `.tmp-quick-*` 下构建、打包；仅供开发自测，不运行完整门禁。
- `npm run deploy` / `npm run release`：真实运行语法、Node 单元及文档检查，失败立即停止；在独立 `.tmp-deploy-*` 生成候选及报告，不自动清理旧包，不操作商店。
- `npm run zip` / `--package-only` 会校验默认 dist 与当前源码；过期、缺失或额外文件被拒绝。不要为了绕过校验使用旧 dist。
- 每个 ZIP 生成 `.verification.json`，校验 source/build/ZIP 文件集合、逐文件 SHA256、CRC、根 manifest、版本与权限；禁止同名覆盖。浏览器和商店放行状态始终单独记录。
- 版本脚本同步 manifest、package、lock 顶层/根包，拒绝非法三段项目版本与原文件不一致；只在后台版本核实及授权后使用。本轮未执行源码升版。
- 依赖审计：`npm audit --registry=https://registry.npmjs.org`。当前镜像不提供审计端点，可用命令参数临时指定官方端点，不改变全局 registry。结果见 [验收报告](../reports/2026-11/EASYCV-W1-W6-LOCAL-ACCEPTANCE.md)，不能用本地测试替代依赖风险处置。


## 📋 部署概述

本文档说明 EasyCV 当前仓库下真实可执行的构建、打包、版本更新与部署准备流程。目标是让维护者能够基于现有脚本完成发布准备，而不是依赖过时模板或占位配置。

## 🛠️ 仓库与环境

### 仓库信息
- **GitHub 仓库**: `https://github.com/fenghuashao/EasyCV`
- **项目 Wiki（对外使用文档）**: `https://github.com/fenghuashao/EasyCV/wiki`
- **默认分支**: `master`
- **扩展规范**: Chrome Extension Manifest V3

### 系统要求
- **浏览器**: Chrome 88+ 或 Edge 88+
- **Node.js**: 建议使用 Node 20+
- **npm**: 建议使用 npm 10+
- **操作系统**: Windows 10+、macOS 10.14+、Linux

### 获取项目
```bash
git clone https://github.com/fenghuashao/EasyCV.git
cd EasyCV
npm install
```

> 说明：当前项目依赖较少，主要开发脚本使用本地 Node.js 运行；`npm install` 会安装打包所需依赖。

## 🏗️ 当前脚本入口

下表对应的是当前 `package.json` 中真实存在的命令：

| 命令 | 当前行为 | 适用场景 |
| --- | --- | --- |
| `npm run docs:check` | 检查索引链接、占位内容、以及索引纳管文档中的仓库路径引用 | 改文档后先跑 |
| `npm run lint` | 对扩展、脚本与测试运行 node --check | 语法检查 |
| `npm run test` | 运行 node:test 单元测试 | 逻辑回归 |
| `npm run build` | 执行 `scripts/build.js`，先校验 manifest、HTML 脚本与 `importScripts` 引用完整性，再复制扩展文件到 `dist` 并生成构建信息 | 本地构建、发布前验证 |
| `npm run package` | 执行 `build + zip`，生成发布包 | 需要 ZIP 发布包时 |
| `npm run zip` | 执行 `scripts/package.js`，把现有 `dist` 打包到 `releases` | 已构建后单独打包 |
| `npm run clean` | 执行 `scripts/clean.js`，清理构建产物、发布产物与常见临时文件 | 重新构建前清理 |
| `npm run bump:patch` / `minor` / `major` | 执行 `scripts/bump-version.js`，同步更新 `package.json`、`manifest.json` 与 `CHANGELOG.md` | 版本递增 |
| `npm run release` | 执行 `clean + build + package` | 本地完整发布准备 |
| `npm run deploy` | 执行 `scripts/deploy.js` 的完整部署流程 | 需要统一跑验证、构建、打包时 |
| `npm run deploy:patch` / `minor` / `major` | 先更新版本，再执行部署流程 | 发版时顺带递增版本 |
| `npm run deploy:build-only` | 仅执行构建 | 验证构建是否正常 |
| `npm run deploy:dry-run` | 预览部署步骤，不实际修改文件 | 发布前检查流程 |

## 📦 推荐发布准备流程

### 1. 文档与基础校验
```bash
npm run docs:check
npm run lint
npm run test
```

> 1.1.2 本轮仅做本地整改和打包，不调用 deploy/release，不 commit/push/提交商店。真实 Chrome 人工验收与商店原包比对缺口见 [权限整改报告](../reports/2026-11/EASYCV-1.1.2-PERMISSION-FIX.md)。本地检查通过不代表商店审核通过。

### 2. 构建与打包
```bash
npm run build
npm run package
```

构建成功后：
- 扩展文件会输出到 `dist`
- ZIP 发布包会输出到 `releases`
- 打包脚本会生成发布说明，并在 Windows/macOS 上尝试自动解压 ZIP 供快速检查

### 3. 带版本更新的发布准备
```bash
npm run deploy:patch
```

该流程会依次执行：
1. 环境验证
2. 内置测试步骤（当前为脚本内模拟流程）
3. 版本更新
4. 清理旧产物
5. 重新构建
6. 打包
7. 生成部署报告

### 4. 仅预览部署流程
```bash
npm run deploy:dry-run
```

适合在真正发版前先确认步骤顺序、版本更新与构建打包策略。

## 🔢 版本管理

当前版本管理由 `scripts/bump-version.js` 负责：

- 同步更新 `package.json`
- 同步更新 `manifest.json`
- 自动写入 `CHANGELOG.md`

版本规则：
- **patch**: 问题修复
- **minor**: 向下兼容的新功能
- **major**: 不兼容变更

常用命令：
```bash
npm run bump:patch
npm run bump:minor
npm run bump:major
```

## 📁 当前产物说明

### 构建产物
- `dist` 目录：可直接用于浏览器“加载已解压的扩展程序”
- `build-info.json`：记录构建时间与构建号

### 发布产物
执行打包后，通常会生成：
- ZIP 发布包，命名模式为 `EasyCV-v<version>-YYYYMMDD.zip`
- 发布说明，命名模式为 `EasyCV-v<version>-README.md`

执行 `npm run deploy` 或 `npm run deploy:<type>` 时，还会额外生成部署报告 `deploy-report.json`。

这些文件由脚本生成，默认输出到 `releases` 目录。

## 🧪 发布前人工检查

在当前仓库状态下，建议至少完成以下人工检查：

- [ ] `npm run docs:check` 通过
- [ ] `npm run build` 通过
- [ ] 能在 Chrome 中成功加载 `dist`
- [ ] Popup、Options、Content Script 基本功能可用
- [ ] 版本号与 `manifest.json` 一致
- [ ] 打包后的 ZIP 可以正常解压并加载

## 🌐 商店发布与手动分发

### Chrome Web Store / Edge Add-ons
当前仓库**没有**内置商店自动发布脚本。商店发布仍需人工完成：

1. 本地执行 `npm run package` 或 `npm run deploy`
2. 取生成的 ZIP 发布包
3. 登录对应的商店后台
4. 上传 ZIP、填写商店描述、截图和隐私说明
5. 提交审核

### 手动分发
如果只是内部试用或手动安装：

1. 运行 `npm run build`
2. 直接加载 `dist` 目录  
   或
3. 运行 `npm run package`，分发 ZIP 后由接收者解压加载

## 🔧 常见问题

### `npm run build` 失败
- 检查 `manifest.json` 是否有效
- 检查 `background`、`content`、`popup`、`options`、`utils`、`icons` 是否存在

### `npm run package` 失败
- 先确认 `dist` 已存在
- 重新执行 `npm run build`
- 再执行 `npm run package`

### `npm run deploy` 失败
- 先执行 `npm run deploy:dry-run` 查看流程
- 检查版本号写入是否正常
- 检查 `releases` 目录是否被其他程序占用
