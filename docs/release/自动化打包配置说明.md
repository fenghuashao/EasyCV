## 📋 概述

本文档聚焦 EasyCV 当前仓库里与构建、打包、版本更新、自动化部署直接相关的脚本实现，帮助维护者快速理解每个脚本负责什么、会产出什么、应该在什么场景使用。完整发布顺序、人工检查与商店提交流程以[部署文档](./部署文档.md)为准，本文不重复维护那套步骤。

## 🛠️ 当前脚本组件

| 文件 | 功能 | 当前职责 |
| --- | --- | --- |
| `scripts/build.js` | 构建 | 校验 `manifest.json`，复制扩展源文件到 `dist`，生成 `build-info.json` |
| `scripts/package.js` | 打包 | 读取 `dist` 中的版本信息，生成 ZIP 包与发布说明，并尝试自动解压 |
| `scripts/quick-package.js` | 快速打包 | 复用 build/package 两步的核心逻辑，一步产出 ZIP，不生成发布说明、不自动解压；包名带 `quick` 标记与秒级时间戳，供开发自测使用 |
| `scripts/clean.js` | 清理 | 清理构建产物、发布产物与常见临时文件 |
| `scripts/bump-version.js` | 版本更新 | 同步更新 `package.json`、`manifest.json` 与 `CHANGELOG.md` |
| `scripts/deploy.js` | 部署编排 | 串联环境验证、测试、版本更新、清理、构建、打包与部署报告生成 |
| `scripts/check-docs.js` | 文档验收 | 检查索引链接、占位内容和索引纳管文档中的仓库路径引用 |

## 🚀 命令入口速查

### 基础命令
```bash
npm run docs:check
npm run build
npm run package
npm run package:quick
npm run clean
npm run release
```

对应行为：
- `docs:check`：运行文档验收检查
- `build`：生成 `dist`
- `package`：执行 `build + zip`
- `package:quick`：快速打包，一步完成 `build + zip`，生成 ZIP 与校验回执（Windows 也可双击 `scripts/package-quick.bat`，脚本会切换至仓库根目录）
- `clean`：删除 `dist`、发布产物与常见缓存/日志
- `release`：执行 `clean + build + package`

### 版本管理
```bash
npm run bump:patch
npm run bump:minor
npm run bump:major
```

这些命令会调用 `scripts/bump-version.js`，自动保持版本号同步，不需要再手动修改 `manifest.json`。

### 部署命令
```bash
npm run deploy
npm run deploy:patch
npm run deploy:minor
npm run deploy:major
npm run deploy:build-only
npm run deploy:dry-run
```

当前行为：
- `deploy`：执行完整部署流程
- `deploy:patch/minor/major`：先更新版本，再部署
- `deploy:build-only`：只构建，不打包
- `deploy:dry-run`：只打印流程，不实际执行

## 📁 产物说明

### 构建阶段
运行 `npm run build` 后：
- 生成 `dist` 目录
- 生成 `build-info.json`

### 打包阶段
运行 `npm run package` 后：
- 生成 ZIP 发布包，文件名包含版本号与日期
- 生成发布说明文件，文件名包含版本号

运行 `npm run package:quick` 后：
- 只生成 ZIP 快速包，文件名形如 `EasyCV-v<版本>-quick-<日期>-<时分秒>.zip`，与正式发布包区分
- 不生成发布说明、不自动解压

运行 `npm run deploy` 或 `npm run deploy:<type>` 时，还会额外生成部署报告 `deploy-report.json`。

这些文件默认输出到 `releases` 目录。

## 🔧 脚本行为要点

### `build.js`
- 当前项目不是 webpack 构建链
- 它直接复制扩展运行所需目录和文件
- `manifest.json` 是构建前的第一道硬校验

### `package.js`
- 依赖 `dist/manifest.json` 读取版本号
- 如果没有先构建，会直接失败
- 会生成 ZIP 包和发布说明
- Windows / macOS 环境下会尝试自动解压，方便快速检查

### `clean.js`
- 默认清理：构建产物、发布目录、临时目录和常见日志文件
- 某些缓存目录即使不存在，也不会影响脚本执行

### `deploy.js`
- 统一部署入口
- 可选执行版本更新
- 会生成部署报告，便于回顾每一步是否成功
- 当前“测试”步骤由脚本内置流程模拟，不等同于真实自动化测试框架

## 🔍 常见问题

### 为什么 `package` 会失败？
最常见原因是没有先生成 `dist`。先运行 `npm run build` 再重试。

### 为什么文档里不再写 webpack / jest / eslint 配置？
因为当前仓库的真实脚本入口并不是这些工具，文档需要和现状对齐，而不是继续沿用模板配置。

### 为什么部署报告不直接写死完整文件路径？
因为这些文件是运行时产物，命名会随版本和日期变化。文档只保留稳定规则，避免再次漂移。
