“简单CV (EasyCV)”插件功能需求文档 (PRD) V1.0
2026-11-03 开发态修订（未打包/发布，优先于下文早期交互设想）：
* Popup 主按钮及子开关保持现有全局配置语义，并明确说明跨页面同步和站点规则的优先级。
* 状态提示区分启用配置与真实复制效果；“检查复制状态”仅查询开关，不能以消息成功替代实际复制验证。
* 已排除页面、不支持的浏览器/商店页面、内容脚本未连接分别提供可行动的说明。
* 当前源码支持英文、简体中文、日语、繁体中文，跟随浏览器界面语言；未支持语言回退英文，其他语言暂缓。帮助为本地四语言指南，不使用联网翻译。
* 反馈打开 GitHub 待编辑草稿；仅预填扩展版本，网站/复现步骤由用户填写并自行提交。下文 4.3 自动附带页面 URL 和提交后自动感谢的早期设想不适用于当前流程。

1. 文档概述
1.1 项目愿景
开发一款Chrome扩展插件，旨在为广大普通互联网用户提供一个极其简单、可靠且值得信赖的解决方案，以解除网页上的复制和粘贴限制。我们的核心是通过卓越的用户体验和清晰友好的反馈，而不是单纯堆砌功能，来赢得用户的信任和喜爱。
1.2 背景与要解决的问题
当前市场上的同类插件普遍存在以下问题：
* 功能失效：在面对现代网站复杂的限制技术时，成功率不高。
* 体验不佳：操作繁琐，甚至会破坏原网站的正常功能。
* 信任缺失：权限请求宽泛，用户对隐私安全感到担忧。
本插件旨在解决这些痛点，成为用户在遇到“禁止复制”或“禁止粘贴”时的首选解决方案。
2. 目标用户
广大的普通互联网用户。
这类用户的典型特征是：
* 不具备深厚的技术背景。
* 希望问题能被“即时”、“无感”地解决。
* 讨厌复杂的设置和令人困惑的界面。
* 对挫败感和不确定性的容忍度低。
3. 产品核心原则
* 清晰友好，永远在线：用户的每一次交互都应得到即时、明确且友好的反馈。绝不让用户感到困惑或被动等待。
* 用户掌控，操作自主：插件的任何核心操作都必须由用户主动发起。我们提供工具，但决策权永远在用户手中。
* 极致透明，赢得信任：通过开源代码和坦诚的沟通，建立产品的信任基石。我们相信，信任比功能更重要。
4. 功能需求 (V1.0)
4.1 核心交互：插件弹出窗口 (Popup)
当用户在工具栏点击插件图标时，应弹出一个简洁的窗口，提供清晰、独立的操作选项。
* 用户故事: 作为一个用户，当我在一个网站上无法复制或粘贴时，我希望能清晰地看到“解锁复制”和“解锁粘贴”的选项，并能分别对它们进行操作。
* 设计要求:
   * 界面上应并排或纵向排列两个主要的操作开关按钮：[解锁复制] 和 [解锁粘贴]。
   * 每个按钮都应能独立操作，并能独立显示其状态反馈。
   * 提供一个不干扰主操作的入口，用于进入“设置”页（见4.4）。
4.2 核心流程：解锁与反馈系统
这是产品的核心功能闭环，针对每个独立的操作开关生效，直接体现了我们的“清晰友好”原则。
* 用户故事: 作为一个用户，当我点击“解锁复制”或“解锁粘贴”按钮后，我希望立刻知道这个具体操作的结果是什么，无论成功还是失败。
4.2.1 状态一：解锁成功
* 触发条件: 用户点击[解锁复制]或[解锁粘贴]后，插件成功解除了对应的页面限制。
* 界面反馈:
   * 视觉: 在被点击的按钮旁显示一个绿色的大对勾 ✓ 图标。
   * 文案: 显示主要文案。例如，点击[解锁复制]后显示“搞定！现在可以复制了。”；点击[解锁粘贴]后显示“搞定！现在可以粘贴了。”
   * 交互: 该成功状态显示约2秒后，弹出窗口自动关闭，方便用户立即进行相应操作。
4.2.2 状态二：需要强力模式
* 触发条件: 标准模式无法解除对应的限制（复制或粘贴），但插件检测到可以通过刷新页面的方式进行更深度的破解。
* 界面反馈:
   * 视觉: 在被点击的按钮旁显示一个黄色的感叹号 ! 图标。
   * 文案: 显示主要文案“这个页面有点顽固，要试试强力模式吗？”
   * 辅助文案: 在下方用小字清晰标注：“（注意：这会刷新当前页面）”。
   * 交互: 界面上出现两个按钮：[刷新试试] 和 [算了]。用户点击[刷新试试]后，插件执行刷新并尝试对刚才失败的操作进行强力破解；点击[算了]则关闭弹出窗口。
4.2.3 状态三：解锁失败
* 触发条件: 即便使用强力模式，也无法解除对应的限制。
* 界面反馈:
   * 视觉: 在被点击的按钮旁显示一个中性的摊手表情符号 (🤷)。
   * 文案: 显示主要文案“抱歉，这个页面的“防御”太特殊，我尽力了。”
   * 交互: 在主文案下方，提供一个低调的链接 “[报告此网站，帮助我们改进]”。此状态会一直保持，直到用户主动关闭窗口。
4.3 用户反馈渠道
* 用户故事: 作为一个用户，当插件无法解决我的问题时，我希望能有一个简单的方式告诉开发者，以便他们未来能修复这个问题。
* 设计要求:
   * 用户点击 [报告此网站，帮助我们改进] 链接后，界面上出现一个简短的输入框。
   * 输入框的提示文字为：“可以简单说下遇到的问题吗？（选填）”。
   * 下方有一个 [提交反馈] 按钮。
   * 提交反馈时，插件应附带当前页面的URL以及用户尝试失败的操作类型（解锁复制/解锁粘贴），以便精准定位问题。
   * 点击提交后，链接变为“感谢您的反馈！”，随后窗口自动关闭。
4.4 设置页面：自动开启列表
为了提升高频用户的效率和灵活性，我们提供了一个可精细化配置的列表，让插件可以根据用户的特定偏好，在指定的网站上自动激活相应的功能。
* 用户故事: 作为一个用户，我希望插件能记住我对不同网站的特定需求。例如，在某个代码论坛我只想自动解锁复制功能，而在另一个在线表格应用中我只想自动解锁粘贴功能。我希望设定一次后，插件就能在我访问这些网站时自动执行，无需我每次都手动操作。
* 设计要求:
   * 在插件弹出窗口的角落（如右下角）放置一个不显眼的齿轮⚙️图标，作为设置页的入口。
   * 设置页面极其简洁，仅包含“自动开启列表”一个功能。
   * 输入范围明确: 用户添加网址时，应有明确提示，输入框仅支持域名 (如 example.com) 和 IP地址 (如 192.168.1.1) 格式。不支持具体的路径或参数。
   * 精细化控制: 在添加每个网址时，用户可以选择需要自动开启的功能：
      * 仅解锁复制
      * 仅解锁粘贴
      * 全部解锁（复制和粘贴）
   * 清晰的列表展示: 列表应清晰地展示已添加的网站及其对应的自动开启设置（例如，使用不同的图标或标签来区分）。
   * 自动执行: 当用户访问列表中的网站时，插件将根据该网站的预设，自动运行指定的一个或多个解锁程序。
   * 在设置页面的显眼位置，放置我们的隐私承诺（见5.1）。
4.5 开发与测试细节说明
为确保开发和测试的顺利进行，特此补充以下交互细节：
* 按钮处理中状态：
   * 定义：当用户点击 [解锁复制] 或 [解锁粘贴] 按钮后，在插件处理并返回结果前的短暂期间，被点击的按钮应立即进入一个视觉上的“处理中/禁用”状态（例如，变为灰色或显示加载动画）。
   * 目的：防止用户在等待期间重复点击同一按钮，确保操作的原子性。此时，另一个未被点击的按钮应保持可操作状态。
* 交互冲突处理：
   * 定义：当插件处于任何即将自动关闭的倒计时状态时（如解锁成功后），如果用户在此期间进行了任何其他有效的操作（如点击另一个解锁按钮），则即将到来的自动关闭倒计时应立即被取消或重置。
   * 目的：确保用户有足够的时间完成他们想进行的所有操作，避免因窗口过早关闭而中断用户流程。
* “自动开启”网站的首次交互：
   * 定义：当用户访问一个已在“自动开启列表”中并被成功自动解锁的网站时，如果用户此时点击浏览器工具栏中的插件图标，弹出的窗口应直接显示对应的成功状态（例如，一个或两个绿色对勾✓及成功文案）。
   * 目的：向用户提供一个明确的确认，告知他们插件已经按预设自动完成了工作。这个成功状态的弹窗可以同样在显示约2秒后自动关闭。
5. 非功能性需求
5.1 安全与隐私
* 终极透明原则: 本项目将在GitHub上完全开源，接受社区的公开监督。
* 隐私承诺: 在设置页和Chrome商店页面明确声明：“我们郑重承诺：绝不追踪您的浏览历史，绝不收集您的个人数据。您的信任高于一切。”
* 最小权限: 仅申请运行所必需的最低权限。
5.2 性能
* 轻量化: 插件本身应尽可能小，不占用过多系统资源。
* 无感运行: 在未激活状态下，插件对浏览器性能的影响应忽略不计。
6. 成功衡量指标 (V1.0)
* 北极星指标: 用户增长与留存率。我们关注周活跃用户（WAU）的持续增长，以及30天用户留存率。高留存率是产品无害且可靠的最佳证明。
* 次要指标:
   * Chrome应用商店评分: 保持在4.8分以上。
   * 卸载率: 保持在较低水平。
   * 核心功能成功率: 内部追踪的 成功解锁次数 / 总尝试次数，用于指导技术迭代。
7. V1.0 不包含的功能 (Out of Scope)
为了确保V1.0的简洁和专注，以下功能将不被包含：
* 复杂的、可自定义的破解规则。
* 针对特定网站（如百度文库、道客巴巴）的专门优化。
* 云端同步“自动开启列表”。
* 皮肤或主题切换功能。
