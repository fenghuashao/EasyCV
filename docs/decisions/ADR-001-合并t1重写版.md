# ADR-001：以 EasyCV 为主体合并 t1 重写版

- 日期：2026-08-06
- 状态：已接受

## 背景

`t1/` 目录是 EasyCV 的一次 PRD 驱动的精简重写（扁平单文件结构、i18n、Shadow DOM 穿透、SPA 感知、单按钮 UX），与 EasyCV 主仓库（模块化结构、全功能、工程化脚本、git 历史）并存。两个实现功能重叠少、互补性强，继续并行会导致解锁逻辑双份维护。

## 决策

以 EasyCV 仓库为主体，吸收 t1 的四项资产，t1 归档：

1. **Shadow DOM 穿透** —— 移植到 `content/injector.js`，并超越 t1 的一次性快照实现：包装 `Element.prototype.attachShadow` 覆盖动态创建的 root（含 closed 模式），样式经 `adoptedStyleSheets` 注入（`root.innerHTML` 赋值会清空 `<style>` 子元素，该属性不受影响）。
2. **SPA 路由感知** —— 移植到 `content/content.js`：`popstate` + MutationObserver 检测 `location.href` 变化，去抖后重置元素去重缓存并重放解锁。
3. **i18n 体系** —— 采用标准 `_locales`（zh_CN 默认 + en），静态文案 `data-i18n` 扫描、动态文案 `I18nUtils.t()`；**不移植** t1 的运行时语言切换（`chrome.i18n` 只跟随浏览器 UI locale，t1 的切换器本就未生效）。
4. **单按钮 UX** —— popup 重构为「一键解锁当前页面」主按钮 + `<details>` 折叠高级区（独立开关、强力模式），保留 EasyCV 的状态模型与统计/快捷操作。

## 一并修复的基座缺陷（合并前置）

- 自动启用读写字段错位（`domainConfig` vs `autoEnableList`），功能曾完全失效
- `submit_feedback` 与 5 种监控消息被 `isValidMessage` 白名单拦截
- `EASYCV_ENABLE`/`EASYCV_DISABLE` 有接收端无发送端，禁用后 main world 原型重写残留；修复后禁用可完整还原（含 `document.on*` 属性劫持）
- popup 统计元素 ID 不一致、`settings.pluginEnabled` 字段名误用（实为 `enabled`）、自动启用列表对象/字符串格式混用
- options 多项设置（`autoDetect` 等）不在 `setPluginSettings` 白名单导致静默丢弃；已扩列

## 放弃的备选方案

- **以 t1 为主体重写**：丢失 git 历史与工程化脚本，需移植 EasyCV 约 80% 功能，工作量大且倒退。
- **抽共享解锁核心、双产品（Lite/Pro）并行**：共享部分仅约 1500 行，收益撑不起双外壳的构建与版本同步成本。

## 影响

- 消息协议、存储 schema 保持 EasyCV 单方体系，无迁移负担（t1 无用户）
- 新增 `_locales/`、`utils/i18n-utils.js`、`test/`（unit + e2e）；`scripts/build.js` 复制清单含 `_locales/`
- popup 交互模型变化：双独立开关默认收起，主按钮为默认路径
- 新增「解锁成功后自动加入自动启用列表」设置（`autoAddToWhitelist`，默认关）
