# EasyCV Documentation Context

This context defines the canonical vocabulary for organizing and maintaining EasyCV's project documentation. It exists so product, engineering, testing, and process documents can be sorted consistently without mixing active references, working notes, and archives.

## Language

**Source Document**:
The canonical document that defines a domain of truth and should be updated when that domain changes.
_Avoid_: primary file, master doc, original doc

**Reference Document**:
A stable document people consult repeatedly to understand how the project works or how to perform a task.
_Avoid_: manual, guide,说明书

**Working Document**:
A time-bounded document used to drive active planning, execution, or coordination during a specific phase.
_Avoid_: temp doc, scratch doc,过程稿

**Evidence Document**:
A document that records what was tested, observed, or concluded at a specific time.
_Avoid_: proof, snapshot, result note

**Governance Document**:
A document that defines how the team writes, updates, reviews, or maintains project artifacts.
_Avoid_: process note, convention list

**Archive**:
Material kept for historical traceability that is no longer the default place to look for current truth.
_Avoid_: old docs,废弃文档

**Asset**:
A supporting artifact such as a diagram, template, or utility file that helps produce documentation but is not itself a source of project truth.
_Avoid_: attachment, misc file
