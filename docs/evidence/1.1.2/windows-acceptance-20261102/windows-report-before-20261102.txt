## 同 ID 升级路径核查

**本轮已确认包身份，尚未确认 Windows 中已安装该包。** Google 官方公开更新请求本次返回 1.1.1：ID `bnbmgiidicjdbnmkmdnjeelhijnlhnjb`，137031 字节，SHA256 `71804c76f85b30fc3b78c16a631f72fbcaa5d983a71ba8aedd47372ab9472cef`，与历史官方 CRX 逐字节相同。本轮重新执行既有只读签名脚本退出 0：三份 CRX3 签名有效，含绑定原 ID 的 item-key proof；36 个运行资源及已解释的 manifest/元数据差异仍匹配。见[本次请求与复验记录](docs/evidence/1.1.2/windows-acceptance-20261101/store-current-check.json)。这仅代表本次公开请求，不代表已读取认证后台或所有地区分发状态。

路径评估见[结构化记录](docs/evidence/1.1.2/windows-acceptance-20261101/upgrade-path.json)：

- **正常原商店商品更新**是可信路径；浏览器可在扩展管理页发起检查，扩展需进入 idle 才能应用。本次端点未给出 1.1.2；未上传、提交或发布。[官方更新生命周期](https://developer.chrome.com/docs/extensions/develop/concepts/extensions-update-lifecycle)。
- **开发模式添加 `key` 保持 ID**仅解决开发身份，不足以证明原商店安装原位升级；本任务禁止修改 ID，不执行此替代实验。[官方 key 说明](https://developer.chrome.com/docs/extensions/reference/manifest/key)。
- **自托管/企业策略**须有可信签名包和受支持、已授权的部署环境；当前均未建立。未生成密钥、重签包、改 update_url、注册表、企业策略或安装安全边界。[官方部署限制](https://developer.chrome.com/docs/extensions/how-to/distribute/install-extensions)、[CRX 更新签名要求](https://developer.chrome.com/docs/extensions/how-to/distribute/host-on-linux)。
- **另建 BETA/私有商品**不能证明原商品 ID 的升级，且需新的商店操作，不执行。官方说明并行测试可以另建商品；原商品渠道变更还可能涉及下架/重发，不能默认为无影响的测试方法。[官方商品更新流程](https://developer.chrome.com/docs/webstore/update)。

因此保持 NOT_VERIFIED，不宣称所有预发布路径均不可能。最小后续是：Windows 就绪后先以隔离 Profile 正常安装原 ID 1.1.1，等待初始化完成，用 UI 写入并保存非默认设置和两类名单；保留该安装及 Profile，取得经过来源/签名核验、可在受支持路径原位更新的同 ID 1.1.2，再核对完整设置/名单及真实网页功能，正常退出、重启后重验。若只能等获批发布后才有该更新，则升级 Gate 继续保留；是否接受发布例外由 FA 单独决定，不能为了验收自行提交或发布。

不得卸载重装、手工复制存储、编辑浏览器 Preferences、模拟 onInstalled/update、用 runtime.reload 或新路径重新 loadExtension 代替真实升级；也不能以下载 CRX、读到存储值或 Worker 存在声称已安装/已升级/功能正常。
