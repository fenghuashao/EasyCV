## ✅ 当前支持范围（唯一真相来源）

### 浏览器支持

当前项目的对外支持范围是：

- **Chrome 88+**
- **Edge 88+**

当前**不把 Firefox 纳入已支持范围**，也不把 Firefox 作为发布前必测浏览器。

### 测试页面与真实页面

当前测试分两类场景：

1. **本地验证页**
   - `test-page.html`
   - 用于验证基础解除能力、UI 操作和回归流程

2. **代表性真实页面**
   - 新闻 / 文档 / 学术 / 博客类页面
   - 用于验证不同限制模式和真实网站兼容性

## 🧪 当前测试层次

当前项目的测试层次按“已经接入的现实能力”划分，而不是按理想测试金字塔描述。

### 1. 验收缝校验

这是当前已经接入的基础自动化门槛：

- `npm run docs:check`
- `npm run build`

说明：

- `npm run lint` 当前仍是占位入口
- `npm run test` 当前仍是占位入口
- 因此 **lint/test 不能被当成真实自动化测试通过的证据**

### 2. 手工功能验证

这是当前最主要的功能验证方式：

- 基于 [功能验证指南](./功能验证指南.md) 执行
- 在 `test-page.html` 上完成核心功能 smoke test
- 在代表性真实页面上完成关键场景验证

### 3. 证据留存

历史测试报告只用于记录过去某一阶段做过什么、发现过什么，不作为当前支持范围或当前发布标准的唯一依据。

## 📊 当前测试目标

### 主要目标

1. **功能验证**：确保当前版本核心能力可以手工复现并验证
2. **范围一致性**：确保测试文档对支持范围和执行方式表述一致
3. **发布前把关**：确保发布前至少完成当前已接入的校验与核心手工验证
4. **兼容性确认**：确认 Chrome / Edge 的关键路径可用
5. **风险识别**：把未自动化的部分明确暴露，而不是隐含假设已覆盖

## 📌 发布前最低门槛

发布前，至少需要满足以下条件：

- [ ] `npm run docs:check` 通过
- [ ] `npm run build` 通过
- [ ] Chrome 上完成 P0 核心功能验证
- [ ] Edge 上完成 P0 smoke 验证
- [ ] 没有阻塞发布的 P0 / P1 缺陷

如果本次改动涉及以下内容，还需要追加验证：

- **状态同步 / 消息机制**：验证多标签页状态同步
- **存储结构变更**：验证设置持久化与回读
- **Popup / Options 改动**：验证界面流程和设置保存
- **DOM / Injector 改动**：验证真实页面限制解除效果

## 🔍 测试范围

### P0 核心验证范围

- 插件安装与加载
- Popup 状态展示
- 插件启用 / 禁用
- 文本选择限制解除
- 右键菜单恢复
- 复制快捷键恢复
- 基础状态同步

### P1 重要验证范围

- 强力模式
- 自动开启列表
- Options 设置保存
- 统计信息展示
- 错误处理与恢复

### P2 探索性验证范围

- 长时间运行稳定性
- 特殊页面结构
- 边界网站兼容性
- 性能与资源占用深入观察

## 🌐 兼容性测试矩阵

## 🧭 执行方式

### 日常开发

1. 改文档时运行 `npm run docs:check`
2. 改功能时运行 `npm run build`
3. 在 `test-page.html` 上做核心 smoke 验证
4. 如影响用户路径，再补真实页面验证

### 发布前验证

1. 运行 `npm run docs:check`
2. 运行 `npm run build`
3. 按 [功能验证指南](./功能验证指南.md) 执行 P0 / P1 手工验证
4. 记录结果到新的测试报告或发布记录中
